# Маршрутизация Kafka по ключу партиции

[English](kafka-partition-keys.md) | [Русский](kafka-partition-keys.ru.md)

Каждый producer MassTransit Kafka Rider в платформе проставляет в исходящую запись явный ключ партиции. Ключ
регистрируется через `AddPartitionKeyedProducer<T>` в
[`KafkaPartitionKeyExtensions.cs`](../../src/Libraries/IntegrationBus.Shared/Extensions/KafkaPartitionKeyExtensions.cs).

## Зачем нужны ключи

Kafka определяет партицию записи по хешу ключа. Все записи с одним ключом попадают в одну партицию, а партицию в
каждый момент читает ровно один участник consumer-группы. Поэтому маршрутизация по ключу даёт две гарантии:

* все операции над одним финансовым счётом обрабатывает одна реплика сервиса, в порядке отправки;
* все события саги одной транзакции попадают на одну реплику оркестратора, в порядке отправки.

Без ключа producer распределяет записи по партициям (sticky round-robin), и две реплики могут обрабатывать
сообщения одного счёта одновременно и в произвольном порядке.

## Выбор ключа

| Семейство сообщений | Ключ | Причина |
| :--- | :--- | :--- |
| `StartTransactionSaga`, события результата саги, `CheckComplianceLimits`, `WriteLedgerRecord`, `ConfirmAccountBalance` | `TransactionId` | Команды и события одной саги упорядочены в одной партиции. |
| `HoldAccountBalance` | `AccountFromId` | Холды по одному счёту-источнику выполняются последовательно. |
| `ReleaseAccountBalance`, `TopUpAccountBalance` и его события результата | `AccountId` | Изменения баланса одного счёта выполняются последовательно. |
| `SeedAccountDatabaseBulkData` и его события результата | нет | Массовая команда не привязана к одному счёту или транзакции. |

Ключ — строка идентификатора в нижнем регистре с дефисами (`Guid.ToString("D")`).

## Проверка

Тест `KafkaPartitionKeyRoutingTests` в `tests/IntegrationBus.Shared.Tests` выполняется на реальном брокере Kafka и
проверяет, что:

* каждая запись содержит идентификатор счёта в качестве ключа, а каждый счёт попадает ровно в одну партицию;
* при двух потребителях в одной consumer-группе каждый счёт обрабатывает ровно один из них, в порядке отправки.
