# 🧑‍🎓 Разворачиваем integration-bus в Kubernetes с нуля (для тех, кто никогда с Kubernetes не работал)

[English](GETTING-STARTED.md) | [Русский](GETTING-STARTED.ru.md)

Эта инструкция написана максимально подробно — по шагам, с объяснением, что и зачем вы делаете, что куда скачивать
и куда класть. Технический разбор архитектуры и найденных багов — в [`README.ru.md`](README.ru.md) рядом с этим
файлом; здесь — только «делай раз, делай два».

Все команды выполняются в терминале (чёрное окошко, куда вводят текстовые команды). Это нормально — Kubernetes
не управляется мышкой, весь мир DevOps работает через терминал. Нужно будет копировать команды из этой инструкции
и вставлять их в терминал, нажимая Enter после каждой.

---

## 0. Что вообще происходит (простыми словами)

- **Docker** — программа, которая умеет запускать «контейнеры»: лёгкие изолированные мини-компьютеры, в каждом из
  которых крутится одна программа (база данных, веб-сервер и т.д.). Это у вас, скорее всего, уже есть и настроено
  — весь этот проект до сих пор запускался через `docker compose up -d`.
- **Kubernetes** («кубер», «K8s») — программа-дирижёр, которая управляет множеством контейнеров автоматически:
  сама перезапускает упавшие, сама распределяет их по серверам. В реальных компаниях Kubernetes работает на
  кластере из десятков серверов. Нам для учебных/локальных целей столько не нужно.
- **Kind** («Kubernetes IN Docker») — утилита, которая создаёт **ненастоящий, но полностью рабочий** кластер
  Kubernetes прямо у вас на компьютере, используя для этого обычный Docker-контейнер вместо настоящего сервера.
  Это и есть наш «мини-кубер».
- **Helm** — программа-установщик для Kubernetes. Вместо того чтобы вручную создавать 40+ отдельных объектов
  (баз данных, очередей, сервисов), вы одной командой говорите Helm «установи вот этот набор инструкций» —
  и он сам создаёт всё по порядку. Это как `apt install` или установщик программы с «Далее → Далее → Готово»,
  только для Kubernetes.
- **kubectl** — утилита, которой вы «разговариваете» с Kubernetes: спрашиваете его статус, смотрите логи и т.д.

Итоговая последовательность: **Docker Desktop** (платформа) → **kind** (создаёт мини-кластер) →
**kubectl** (общается с кластером) → **Helm** (ставит в кластер весь проект одной командой).

## 1. Что нужно скачать и установить (один раз)

### 1.1. Docker Desktop

Если вы уже запускали этот проект через `docker compose up -d` — Docker Desktop у вас уже есть, переходите к
пункту 1.2.

Если нет:
1. Откройте в браузере: `https://www.docker.com/products/docker-desktop/`
2. Нажмите кнопку **Download for Windows**.
3. Запустите скачанный установщик `Docker Desktop Installer.exe`, нажимайте **Ok** / **Next** во всех окнах
   (на шаге с галочкой **«Use WSL 2 instead of Hyper-V»** — оставьте галочку включённой, это важно).
4. Если попросит перезагрузить компьютер — перезагрузите.
5. После перезагрузки запустите **Docker Desktop** из меню Пуск. Подождите, пока в левом нижнем углу окна
   появится надпись **«Engine running»**, а иконка кита в системном трее (рядом с часами) перестанет анимироваться.

**Как проверить, что всё в порядке:** откройте терминал (см. пункт 2) и введите:
```
docker --version
```
Если в ответ напечаталась строка вроде `Docker version 29...` — всё хорошо.

### 1.2. kind

Это не программа с установщиком, а один-единственный файл `kind.exe`, который нужно просто положить в правильную
папку.

1. Создайте (если ещё нет) папку `C:\Users\<ВашеИмяПользователя>\bin`.
2. Откройте в браузере: `https://kind.sigs.k8s.io/dl/v0.25.0/kind-windows-amd64`
   — браузер скачает файл. Переименуйте скачанный файл в `kind.exe` (если он скачался без расширения или с другим
   именем) и переместите его в папку `C:\Users\<ВашеИмяПользователя>\bin`.
3. Нужно, чтобы Windows знала про эту папку (т.н. переменная PATH), иначе набрав `kind` в терминале вы получите
   ошибку «команда не найдена»:
   - Нажмите **Win**, введите **«Изменение переменных среды текущего пользователя»**, откройте.
   - В верхнем списке («Переменные среды пользователя») найдите строку **Path**, нажмите **Изменить**.
   - Нажмите **Создать**, впишите `C:\Users\<ВашеИмяПользователя>\bin`, нажмите **ОК** во всех окнах.
   - **Закройте и заново откройте терминал** — иначе изменение не подхватится.

**Как проверить:**
```
kind --version
```
Ожидается `kind version 0.25.0`.

### 1.3. Helm

Аналогично — один exe-файл, только он лежит внутри zip-архива.

1. Откройте в браузере: `https://get.helm.sh/helm-v3.16.4-windows-amd64.zip`
2. Распакуйте скачанный архив (правой кнопкой → **Извлечь всё**).
3. Внутри распакованной папки найдите файл `helm.exe` (он лежит в подпапке `windows-amd64`).
4. Переместите именно этот `helm.exe` в ту же папку `C:\Users\<ВашеИмяПользователя>\bin`, что и `kind.exe`
   (PATH уже настроен из прошлого шага, второй раз делать не нужно).

**Как проверить:**
```
helm version
```
Ожидается строка, содержащая `v3.16.4`.

### 1.4. kubectl

Уже установлен вместе с Docker Desktop, отдельно скачивать не нужно.

**Как проверить:**
```
kubectl version --client
```

## 2. Как открыть терминал в нужной папке

1. Откройте проводник Windows и перейдите в папку проекта.
2. Кликните в адресной строке проводника (там, где написан путь), сотрите его и впишите `git-bash` → Enter
   — откроется терминал Git Bash прямо в этой папке.
   *(Если Git Bash не установлен — подойдёт обычный **PowerShell**: в адресной строке впишите `powershell` → Enter.
   Команды ниже написаны под Git Bash/Linux-стиль; в PowerShell они тоже работают почти без изменений, отличия
   отмечены отдельно.)*

Все команды из следующих шагов вводите именно в этом окне.

## 3. Создаём мини-кластер Kubernetes

В папке проекта уже лежит готовый конфиг-файл для кластера. Выполните:

```bash
kind create cluster --config deploy/k8s/kind/kind-cluster.yaml
```

Что произойдёт: kind скачает специальный образ-«контейнер-который-притворяется-сервером» (один раз, при первом
запуске это может занять пару минут) и запустит его. В конце вы увидите:
```
Set kubectl context to "kind-integration-bus"
```
Это значит, что `kubectl` теперь «смотрит» именно в ваш новый мини-кластер.

**Как проверить:**
```bash
kubectl get nodes
```
Должна появиться одна строка со статусом `Ready`.

> ⚠️ Если у вас уже где-то запущен docker-compose этого же проекта (`docker compose up -d`) — компьютеру придётся
> тянуть сразу два полных набора из 18 контейнеров, и на слабой машине всё начнёт жутко тормозить и падать.
> Рекомендуется сначала остановить его: `docker compose down` (данные в базах при этом не удаляются, это
> безопасно — вернуть всё назад потом можно командой `docker compose up -d`).

## 4. Собираем образы приложения

«Образ» — это упакованная программа, готовая к запуску в контейнере. У нас 6 своих .NET-сервисов и один
кастомный Kafka Connect — их нужно собрать:

```bash
docker compose build
```

Это может занять несколько минут (компилируется весь .NET-код). Дождитесь, пока терминал снова станет свободным
(появится приглашение для ввода команды).

---

## 5. Загружаем собранные образы в мини-кластер

Образы, собранные в шаге 4, лежат только у Docker на вашем компьютере — мини-кластеру kind нужно явно их
«подарить» (у своих образов нет сервера в интернете, откуда кластер мог бы их сам скачать):

```bash
for img in \
  integration-bus-integration-bus-gateway-api \
  integration-bus-integration-bus-processing-api \
  integration-bus-integration-bus-saga-orchestrator-service \
  integration-bus-integration-bus-account-balance-service \
  integration-bus-integration-bus-compliance-service \
  integration-bus-integration-bus-core-ledger-service \
  integration-bus-integration-bus-kafka-connect \
; do
  kind load docker-image "$img:latest" --name integration-bus
done
```

*(В PowerShell цикл `for` пишется иначе — проще всего скопировать и выполнить 7 строк по отдельности, заменив
`$img` на конкретное имя каждого образа, например: `kind load docker-image integration-bus-integration-bus-gateway-api:latest --name integration-bus`.)*

Остальные образы (Postgres, Kafka, Redis и т.д.) загружать не нужно — у них есть настоящий адрес в интернете, и
кластер скачает их сам на следующем шаге.

## 6. Устанавливаем весь проект одной командой

Сначала создаём «отдельную комнату» внутри кластера для нашего приложения (называется namespace):

```bash
kubectl create namespace integration-bus
```

А теперь — главная команда, которая разворачивает **весь** проект целиком (18 программ: 6 сервисов, база данных,
очередь сообщений, кэш, аналитическая база, дашборды и т.д.):

```bash
helm install integration-bus deploy/k8s/charts/integration-bus -n integration-bus --timeout 10m
```

Эта команда работает **несколько минут** — не пугайтесь, если терминал «висит» 3-5 минут, это нормально:
Kubernetes параллельно скачивает недостающие образы и дожидается, пока каждая часть системы запустится в
правильном порядке. В конце должно появиться:
```
STATUS: deployed
```
Если вместо этого появилась ошибка про таймаут — не страшно, почти всегда помогает повторить ровно ту же команду,
заменив `install` на `upgrade`:
```bash
helm upgrade integration-bus deploy/k8s/charts/integration-bus -n integration-bus --timeout 10m
```

## 7. Проверяем, что всё поднялось

```bash
kubectl get pods -n integration-bus
```

Вы увидите список из ~20 строк. У каждой — колонка `READY` (например `1/1` — значит, всё в порядке) и `STATUS`
(`Running` — работает, `Completed` — это нормально для разовых задач типа настройки, они и должны завершиться).

Чтобы смотреть на обновление списка в реальном времени (а не вводить команду заново каждый раз), добавьте `-w`:
```bash
kubectl get pods -n integration-bus -w
```
(Чтобы выйти из этого режима — нажмите `Ctrl+C`.)

**Это нормально:** в первую минуту-две некоторые из 6 .NET-сервисов могут 1-2 раза перезапуститься (в колонке
`RESTARTS` будет не `0`) — это ожидаемое поведение при самом первом запуске (сервис стартует чуть быстрее, чем
успевают создаться служебные очереди сообщений, и Kubernetes сам перезапускает его через несколько секунд). Если
через 2-3 минуты все строки показывают `Running` и счётчик `RESTARTS` перестал расти — всё хорошо.

**Если что-то не так** — посмотрите подробности конкретного пода (имя пода — это как раз первый столбец):
```bash
kubectl describe pod <имя-пода> -n integration-bus
```
В самом низу будет раздел `Events` с объяснением проблемы.

## 9. Проверяем, что бизнес-логика реально работает

Самый простой способ для человека без опыта в `curl` — скачать и использовать **Postman** (бесплатная программа
с понятным интерфейсом для отправки запросов): `https://www.postman.com/downloads/`. Либо, если вы уже освоились
с терминалом, можно просто скопировать команды из [`docs/business-logic/validation-guide.ru.md`](../business-logic/validation-guide.ru.md), заменив
в них только номера портов на те, что в таблице выше (прибавлены `10000` к обычным).

Коротко, через терминал:
```bash
curl -X POST http://localhost:15038/api/v1/accounts/seed -H "Content-Type: application/json" -d "{\"count\": 5, \"currency\": 1}"
```
Должен прийти ответ с кодом `202` — значит, запрос принят и обрабатывается внутри кластера.

## 10. Как всё выключить, когда закончили

Выключать можно по шагам (от маленького к большому):

```bash
# Удалить только сам проект, оставив мини-кластер работать
helm uninstall integration-bus -n integration-bus
kubectl delete namespace integration-bus

# Полностью снести мини-кластер целиком (освобождает больше всего ресурсов компьютера)
kind delete cluster --name integration-bus
```

Если вы останавливали обычный docker-compose в шаге 3 и хотите вернуться к нему — выполните:
```bash
docker compose up -d
```

## 11. Если что-то пошло не так — короткий FAQ

- **`kind: command not found` / `kind не является внутренней или внешней командой`** — вы забыли закрыть и
  заново открыть терминал после изменения переменной PATH (шаг 1.2). Закройте окно терминала полностью и
  откройте заново.
- **Под навечно висит в статусе `Pending`** — обычно значит, что не хватает места на диске для данных
  (`PersistentVolumeClaim`). Проверьте: `kubectl get pvc -n integration-bus` — все должны быть в статусе `Bound`.
- **Под виснет в `ImagePullBackOff`** — компьютеру не удаётся скачать образ из интернета. Проверьте интернет-
  соединение и повторите `kubectl get pods -n integration-bus` через минуту — обычно само проходит.
- **Один из 6 .NET-сервисов перезапускается больше 3-4 раз подряд и не успокаивается** — посмотрите его логи:
  `kubectl logs <имя-пода> -n integration-bus --previous` и прочитайте последние строки с `ERROR`/`Exception`.
- **Компьютер сильно тормозит, вентилятор ревёт** — это ожидаемо: единовременно работают почти 20 программ.
  Закройте лишние приложения, дайте пару минут на стабилизацию, и по возможности не держите одновременно
  запущенным ещё и обычный docker-compose этого же проекта (см. предупреждение в шаге 3).
