# Что нужно улучшить в документации

> Данный файл по итогу должен быть удален из репозитория после того, как будет завершено улучшение документации.

Если мы целимся в то, чтобы проект был production ready, то документация у него должна быть на соответствующем уровне. 

Мои претензии к документации:
1. Во всех местах и во всех файлах документации, где есть ссылка на md файл из репозитория, нужно использовать ссылку следующего вида: [`docs/data-loading.ru.md`](../data-loading.ru.md).
2. Пройтись по файлам документации и убрать все ссылки, которых нет в проекте (либо поломанные ссылки, либо ссылки на несуществующие файлы, либо ссылки на локальные файлы на локальной машине, которых нет в репозитории). Самый очевидный кандидат — `docs\integration-bus-evolution-roadmap.ru.md`. Проверить все остальные файлы документации на эту проблему и убрать такие ссылки (либо заменить теми файлами, которые есть в репозитории). 
3. Файл `docs\data-analytics\data-loading.ru.md` нужно очень сильно переписать: какие-то странные рассуждения (например, `Мне кажется, что может быть проблема в схеме перегрузки данных, которую мы спроектировали`, `И тут получается трэш: работа с кафкой строится на основе чтения строк в логе и коммите оффсета, и получается, что мы в кликхаус будем заливать изменения по одной записи...`). Нужно переписать файл так, будто описываем уже принятое решение и альтернативные решения, которые "не взлетели". Либо вообще его удалить, если в `docs\data-analytics\README.ru.md` уже всё описано. Убедись, чтобы в других файлах документации не было таких "приколов".
4. Англоязычные файлы должны быть с расширением `.md` (например, `README.md`), а имена русскоязычных файлов должны заканчиваться на `ru.md` (`README.ru.md`). У всех русскоязычных файлов должна быть англоязычная версия (в таком случае в русской и английской версии ставится сслыка на обе версии, например, `[English](README.md) | [Русский](README.ru.md)`); если файл англоязычный, то русская версия не является обязательной.
5. Если файл англоязычный, и он ссылается на свою русскоязычную версию, то это ок. Но если англоязычный файл ссылается на русскоязычную версию другого файла, то это нарушение (например, в основном `README.md`, который написан на английском, есть ссылка на [`GETTING-STARTED.ru.md`](docs/k8s-deployment/GETTING-STARTED.ru.md) — нужно было создать [`GETTING-STARTED.md`](docs/k8s-deployment/GETTING-STARTED.md), а в `README.md` сделать ссылку на англоязычную версию).
- Исключение: если в русскоязычном файле есть ссылка на англоязычный файл, у которого нет русскоязычной версии, то это нормально. Но если в русскоязычном файле есть ссылка на англоязычный файл, у которого есть русскоязычная версия, то это тоже нарушение.
6. Документация должна быть написана так, будто она описывает, как платформа работает сейчас, а не то, какие решения или проблемы произошли в процессе реализации (например, в файле `docs\data-analytics\README.ru.md` почему-то описывается "Пять неочевидных проблем, найденных и исправленных эмпирически" — если такое и описывается, то нужно это подать, как готовый рецепт того, что пользователь может сделать, чтобы это не повторилось, когда он будет разворачивать у себя проект; но если эти проблемы устранены, никогда не будут повторены, и не несут для незнакомого с архитектурой проекта читателя чего-то полезного, то такое стоит удалить). Необходимо проанализировать ВСЕ файлы и исправить такое во всех файлах.
7. Документация должна быть написана так, чтобы когда пользователь открывает её, она отвечала ему на вопрос "Как работает проект прямо сейчас?", а не на вопрос "Какие мелкие проблемы возникли в процессе реализации данного модуля?". Не должно быть намека на "мы сначала решили сделать Решение А, а потом столкнулись проблемами при тестировании и решили сделать Решение Б" — это вообще не интересно читателю, ему интересно то, как проект СЕЙЧАС работает.
